# Phase 6 — Exports

## Goal

Export any report the user can view, saved or unsaved, as CSV, XLSX or PDF,
with all rows (not just the 500-row preview), formatting and totals.

## Success criteria

- CSV streams in chunks at constant memory. XLSX keeps number and currency
  formats and bold totals. PDF is landscape with a title, filters summary,
  generated-at time, KPI tiles, the table with conditional styles and totals,
  and page numbers.
- Exports above 50,000 rows (CSV/XLSX) are queued. The user gets an in-app
  notification (the existing notification system) and an email with a signed,
  expiring download link. PDF is capped at 2,000 rows, and the page says so.
- CSV formula injection is neutralized: cells starting with `= + - @ \t \r`
  are prefixed with `'`.
- Filenames are `slug(report-name)-YYYY-MM-DD-His.ext`.

## Sub-phases

### 6.1 — Exporter contract and CSV — `checkpoint: csv`
- `app/Reporting/Export/{Exporter,CsvExporter,ExportFormat}.php`. `ReportRunner` gets a `cursor()` path for table mode (`lazy()` chunks) and a full-result path for summary and pivot (already capped at 10k groups).
- Route `GET|POST /dashboard/reports/export` taking either `report_id` or an inline definition plus `format`, rate limited at `throttle:10,1`. **The legacy `GET /dashboard/reports/export?group_by=…` keeps working:** when `group_by` is present without a definition, the matching `LegacyPresets` definition is used and the legacy column headers are kept.
- **Done when:** CSV tests (headers, totals row, injection escaping, tenant scope, legacy parameters) pass.

### 6.2 — XLSX — `checkpoint: xlsx`
- `XlsxExporter` using `maatwebsite/excel` (`FromQuery`/`FromArray` + `WithHeadings`, `WithColumnFormatting`, `WithStyles`, `ShouldAutoSize`). The pivot sheet has merged nested headers.
- A second "About" sheet: report name, dataset, filters in plain English, generated by and at.
- **Done when:** tests use `Excel::fake()` assertions plus one real-file test that reads the cells back.

### 6.3 — PDF — `checkpoint: pdf`
- `PdfExporter` using `barryvdh/laravel-dompdf` with the Blade view `resources/views/reports/pdf.blade.php` (inline CSS, no external assets). The semantic styles map to the same palette as the UI.
- The filters summary uses `DefinitionDescriber` (plain-English sentence for the filters), which is shared with XLSX "About" and emails.
- **Done when:** a test checks the PDF renders and contains the expected text (parse with `smalot/pdfparser` only if it's already present; otherwise assert on the rendered HTML before dompdf).

### 6.4 — Queued large exports — `checkpoint: queued`
- `GenerateReportExportJob`: runs as the user, writes to `storage/app/report-exports/{uuid}` and sends a `ReportExportReady` notification (database + mail) with a `URL::temporarySignedRoute` link that expires in 24 h.
- Files older than 48 h are cleaned by a scheduled command in `routes/console.php`.
- **Done when:** job tests cover success, failure notification, link expiry and cleanup.

### 6.5 — UI — `checkpoint: ui`
- The builder Export menu has CSV, Excel and PDF, plus a toast for "Large export, we'll email you when ready". The library row actions get the same menu.
- **Done when:** Playwright downloads a CSV and checks its first row.

## Risks

- dompdf being slow on large tables. That's why the 2,000-row cap is there.
- The queue worker must be running locally (see memory: Reverb/queue local
  setup).
